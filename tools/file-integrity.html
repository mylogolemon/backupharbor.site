Interpret the result

A matching digest is strong evidence of identical bytes, not proof of a complete backup or correct historical version.

File tools read only files you explicitly select, in browser memory (limit 64 MiB per file, 100 files per run). No file contents or results are sent by this tool. No automatic backup or recovery is performed.

Compare the intended versions

Select a trusted original and the file you restored or copied. Run the check, then read both filenames and digests. The two files are processed locally by the page, with a limit of 64 MiB each. Use the supplied non-sensitive Recovery Lab samples first if you want to learn the process without handling important files.

Understand a match or difference

A matching SHA-256 digest is strong evidence that the selected bytes are the same. It does not prove the original was correct or authentic; two copies of a corrupted file can still match. A difference means the selected bytes differ, but it does not identify the cause. You may have chosen a different version or a file that changed during copying.

Complete a restore test

After comparing, open the recovered file in the application you need and verify the intended content and date. Some applications use separate assets or databases that a single-file hash cannot check. Keep originals intact and restore into a separate location when possible. Never paste passwords or recovery codes into exported notes.
